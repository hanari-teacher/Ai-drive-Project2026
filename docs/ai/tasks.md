# AI質問機能 実装計画 (`docs/ai/tasks.md`)

本計画は、標準課題（授業内で必須となる基本実装）と、発展課題（さらなる拡張・発展的な機能）に分類して段階的に進める構成としています。

---

## 1. 共通準備 (Common Prep) 【標準課題】

* **作業ID**: TASK-01
* **対応REQ・DES**: `REQ-AI-N001`, `REQ-AI-N002` / `DES-AI-N001`, `DES-AI-N002`
* **変更対象ファイル**:
* `src/apps/ai/aiRouter.ts` (新規作成)
* `src/apps/ai/aiController.ts` (新規作成)
* `src/apps/ai/aiService.ts` (新規作成)
* `src/apps/ai/aiModel.ts` (新規作成)
* `src/apps/ai/aiMiddleware.ts` (新規作成)

* **作業内容**:
* 既存の `src/apps/todo/` の構成を踏襲し、`src/apps/ai/` 配下にルーター、コントローラー、サービス、モデル、ミドルウェアの空ファイル（または骨組み）を作成する。
* `index.ts` に `/api/ai` ルーターを登録し、ミドルウェアの適用順序（JSON解析、既存ルートの保護、404、エラーハンドラーの順）を整える。

* **確認方法**:
* `npm run dev` でサーバーを起動し、コンソールにエラーが出ず正常に起動することを確認する。

* **期待結果**:
* サーバーが起動し、新規追加したAIディレクトリの骨組みが既存のExpressアプリに組み込まれていること。

## 3. 履歴API (History API) 【標準課題】

* **作業ID**: TASK-03
* **対応REQ・DES**: `REQ-AI-F003`, `REQ-AI-F004` / `DES-AI-F003`, `DES-AI-F004`
* **変更対象ファイル**:
* `src/apps/ai/aiModel.ts`
* `src/apps/ai/aiController.ts`
* `src/apps/ai/aiRouter.ts`

* **作業内容**:
* `aiModel.ts` にデータベースから履歴を全件（または直近順に）取得するクエリ関数を実装する。
* `aiController.ts` と `aiRouter.ts` にて `GET /api/ai/history` エンドポイントを実装し、JSON形式で履歴一覧を返すようにする。

* **確認方法**:
* ブラウザまたはAPIクライアント（cURL等）で `http://localhost:3000/api/ai/history` にアクセスする。

* **期待結果**:
* 履歴が空の場合は空の配列 `{"success": true, "data": []}` が返され、データがある場合は登録済みのQ&AリストがJSONで返されること。

## 4. 模擬回答の保存 (Mock Answer & Save) 【標準課題】

* **作業ID**: TASK-04
* **対応REQ・DES**: `REQ-AI-F002`, `REQ-AI-F003` / `DES-AI-F002`, `DES-AI-F003`
* **変更対象ファイル**:
* `src/apps/ai/aiService.ts` (模擬モジュール)
* `src/apps/ai/aiModel.ts`
* `src/apps/ai/aiController.ts`

* **作業内容**:
* 実AI連携の前に、入力されたプロンプトを受け取り固定の模擬回答（例: 「これはテスト回答です」）を返すモック処理を `aiService.ts` に実装する。
* コントローラーにて、入力値のバリデーション（空文字チェック等。失敗時は即座に400応答）を行い、模擬回答を生成・DBに保存（アトミックな処理）した上で応答を返す `POST /api/ai/ask` を実装する。

* **確認方法**:
* ポストマンやcURL、または簡単なFetchテストで `POST /api/ai/ask` にJSON `{ "prompt": "テスト質問" }` を送信する。

* **期待結果**:
* 模擬回答とプロンプトがDBに保存され、正常なレスポンスが返ること。バリデーションエラー時はAIを呼ばず400が返ること。

## 7. 送信UI (Submit UI) 【標準課題】

* **作業ID**: TASK-07
* **対応REQ・DES**: `REQ-AI-F001`, `REQ-AI-F002` / `DES-AI-F001`, `DES-AI-F002`
* **変更対象ファイル**:
* `public/ai/app.js`

* **作業内容**:
* 質問入力フォームに入力されたテキストを受け取り、`POST /api/ai/ask` へ非同期送信（Fetch）するクライアントサイドロジックを実装する。
* 送信中の待機状態（ローディング表示、ボタン無効化）および、成功時の画面更新（回答表示・履歴リストへの追加）を実装する。

* **確認方法**:
* ブラウザで実際に質問を入力して送信ボタンを押し、ローディングを経てAIからの回答がリアルタイムに画面に表示されることを確認する。

* **期待結果**:
* ページをリロードすることなく、送信から回答表示までのインタラクションがスムーズに行われること。

## 8. 異常系・デモ停止制御 (Error Handling & Demo Control) 【標準課題】

* **作業ID**: TASK-08
* **対応REQ・DES**: `REQ-AI-F005`, `REQ-AI-F006` / `DES-AI-F005`, `DES-AI-F006`
* **変更対象ファイル**:
* `src/apps/ai/aiMiddleware.ts`
* `src/apps/ai/aiController.ts`
* `public/ai/app.js`

* **作業内容**:
* ネットワークエラーやAPIエラー発生時にサーバーがクラッシュしないよう例外処理（グローバルエラーハンドラーへの連携）を実装する。
* クライアント側でエラー発生時に入力テキストを保持し、再送できるようにする。
* 環境変数等によるデモ停止（公開停止）ミドルウェアを `POST /api/ai/ask` に適用し、停止中メッセージを返却する機能を実装する。

* **確認方法**:
* 不正なAPIキーや切断状態を模擬してエラー表示と入力値の保持・再送を確認する。また、公開停止フラグを有効にして `POST` リクエストを送り、停止中メッセージが返ることを確認する。

* **期待結果**:
* エラー時にアプリが落ちず、ユーザーフレンドリーなメッセージが提示され、公開停止時は質問機能が安全に制限されること。
