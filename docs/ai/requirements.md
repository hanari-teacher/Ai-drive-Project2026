# AI質問機能 要件定義書 (`docs/ai/requirements.md`)

## 1. 背景・目的・利用者・対象範囲

### 1.1. 背景・目的

* **背景**: 既存のExpress/TypeScript製Webアプリケーション（TODOアプリ等）に新たな機能としてLLMを活用したAI質問アプリを統合し、ユーザーの学習や業務効率化を支援する。
* **目的**: ユーザーからの質問に対してAIが適切な回答を即座に返し、そのやり取り（履歴）を保存・管理できる仕組みを提供する。

### 1.2. 利用者

* **一般ユーザー**: 質問の入力、AIからの回答閲覧、過去の質問履歴の参照、必要に応じた再送。

### 1.3. 対象範囲

* AI質問画面のUI提供（TOP画面やTODO画面からの導線、または独立した `/ai` ルートの設置）
* サーバーサイド（Express）でのルーティング、コントローラー、サービス層の実装
* データベース（PostgreSQL）への質問・回答履歴の保存および取得
* 外部AI APIとの通信、エラーハンドリング、簡易的な公開停止（メンテナンス）制御

## 3. 機能要件 (REQ-AI-Fxxx)

* **REQ-AI-F001: AI質問インターフェースと導線**
* 既存のTOP画面またはTODO画面からアクセス可能な導線を持ち、ユーザーが自由テキスト形式で質問を入力・送信できるUIを提供する。


* **REQ-AI-F002: 質問の送信とリアルタイム応答表示**
* ユーザーが送信ボタンを押した際、ページをリロードせずにバックエンドへ非同期送信し、AIからの回答を画面上に表示する。


* **REQ-AI-F003: 履歴の保存と閲覧**
* ユーザーが行った質問とAIの回答のペアをデータベースに保存し、過去の履歴として一覧を閲覧できるようにする。


* **REQ-AI-F004: 履歴 0件時の条件**
* データベースに履歴データが一件も存在しない場合、「履歴はありません」等のわかりやすいプレースホルダーメッセージを表示する。


* **REQ-AI-F005: 失敗時の検知と再送条件**
* ネットワークエラーや外部AI APIのタイムアウト等の失敗が発生した場合、サーバー側でクラッシュを防ぎ、クライアントにエラー通知を行う。クライアント側では入力内容を保持したまま再送を行えるようにする。


* **REQ-AI-F006: 公開停止（メンテナンス・停止）の条件**
* 環境変数の切り替え等により、AI機能を一時的に停止状態にし、質問機能の代わりに停止中メッセージを表示できるようにする。



---

## 4. 非機能要件 (REQ-AI-Nxxx)

* **REQ-AI-N001: アーキテクチャの準拠**
* 既存のTODOアプリ（`src/apps/todo/`）と同様に、Router / Controller / Service（Model）の責務分離アーキテクチャを踏襲すること。


* **REQ-AI-N002: 機密情報の管理**
* 外部AIのAPIキーやデータベース接続情報などの秘密値は、ソースコードに直書きせず、`dotenv` を用いた環境変数からのみ読み込むこと（リポジトリへのコミットを禁止する）。


* **REQ-AI-N003: 既存機能への影響排除**
* 既存のTODOアプリ、共通ルーティング、404エラーハンドリング、グローバルエラーハンドラーの動作を一切阻害しないこと。



---

## 5. データ要件 (REQ-AI-Dxxx)

* **REQ-AI-D001: 質問履歴データモデル**
* データベース（PostgreSQL）に質問履歴を保存するためのテーブル構造を定義すること（ID、質問テキスト、回答テキスト、作成日時等）。


* **REQ-AI-D002: 入力バリデーション**
* 空文字の質問や過度に長い質問は、データベース保存およびAPI送信の前にバリデーションにより弾くこと。

## 6. 各要件の受入条件 (Acceptance Criteria)

| 要件ID | 受入条件 (どのような状態であれば合格とするか) |
| --- | --- |
| **REQ-AI-F001** | TOP画面またはTODO画面からリンク経由でAI質問画面に遷移でき、入力フォームと送信ボタンが正しく描画されていること。 |
| **REQ-AI-F002** | 質問を入力して送信した際、ローディング表示を経由してAIからの返答が画面に描画されること。 |
| **REQ-AI-F003** | 質問と回答のやり取りがデータベースに正しく保存され、画面再訪問時に履歴一覧から確認できること。 |
| **REQ-AI-F004** | データベースに履歴が一件もない初期状態において、エラーにならず「履歴がありません」という専用メッセージが表示されること。 |
| **REQ-AI-F005** | APIエラー発生時にアプリがクラッシュせずエラーメッセージが表示され、かつ入力フォームのテキストが保持された状態で「再送」ボタン等から再試行できること。 |
| **REQ-AI-F006** | 公開停止用の環境変数（設定）を有効にした状態でAI画面にアクセスした際、質問フォームの代わりに「現在AI機能は停止中です」というメッセージが表示されること。 |
| **REQ-AI-N002** | ソースコード上にAPIキー等の秘密値が含まれておらず、`.env` ファイルを通じて正常に動作すること。 |
