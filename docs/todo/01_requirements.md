# TODOアプリ 要件定義書 (v1)

## 1. 目的・対象範囲

本ドキュメントは、既存のExpress + TypeScript + EJS構成のWebサイトに新規追加する「TODOアプリ（v1）」の要件を定義するものです。
既存のルート（`/` および `/api/db-check`）はそのまま維持し、TODO画面は `/todo` に配置します。データベースには学生自身のNeon PostgreSQLを使用し、Vercelへデプロイします。Preview環境とProduction環境は同一のNeon DBを参照するため、個人情報は扱わず架空のテストデータのみを使用します。
なお、v1における対象範囲は、認証、優先度設定、絞り込み、タイトル更新を除外し、基本的なCRUD操作（一覧、登録、完了状態の更新、削除）に限定します。内部の細かいファイル配置やモジュール分割の詳細については要確認とし、設計書（`docs/todo/02_design.md`）にて決定します。

## 2. 4機能と受け入れ条件

### REQ-01: TODO一覧取得

* **操作:** サーバーから登録されているすべてのTODOタスクを取得する。
* **エンドポイント:** `GET /api/v1/todos`
* **入力:** なし
* **結果:** 成功時はステータスコード `200 OK` を返し、JSONボディとしてタスクの一覧（配列）を返す。タスクが0件の場合は `200 OK` とともに `{"data": []}` を返す。
* **エラー:** 500（サーバー内部エラー）、503（データベース接続エラー等）。
* **受け入れ条件:**
* データベースに保存されている全タスクが正しく取得できること。
* 登録データが0件の場合、エラーにならず `{"data": []}` が返却されること。

* **確認方法:** ブラウザで `/todo` にアクセスし画面上で一覧が表示されること、または `curl` 等で `GET /api/v1/todos` を実行して確認する。

### REQ-02: TODO登録

* **操作:** 新しいTODOタスクを登録する。
* **エンドポイント:** `POST /api/v1/todos`
* **入力:** JSONボディ `{"title": "タスクのタイトル"}`
* **結果:** 成功時はステータスコード `201 Created` を返し、作成されたタスクのオブジェクトを返す。
* **エラー:** 400（不正なリクエスト／JSONパースエラー）、422（バリデーションエラー）、500、503。
* **受け入れ条件:**
* `title` は前後の空白を除去（trim）した上で、1文字以上100文字以内であること。
* 空白のみ、あるいは未入力、100文字超の場合はステータスコード `422` を返すこと。

* **確認方法:** `/todo` 画面の入力フォームにタイトルを入力して登録ボタンを押し、一覧に即時反映されること、または `curl` で不正なデータを投げてエラーコードを確認する。

### REQ-03: TODO完了状態の部分更新

* **操作:** 指定したIDのTODOタスクの完了状態（completed）を更新する。
* **エンドポイント:** `PATCH /api/v1/todos/:id`
* **入力:** パラメータ `:id`（1以上の整数）、JSONボディ `{"completed": true または false}`
* **結果:** 成功時はステータスコード `200 OK` を返し、更新されたタスクのオブジェクトを返す。
* **エラー:** 400（IDやボディの型不正）、422（バリデーションエラー）、404（指定IDのタスクが存在しない）、500、503。
* **受け入れ条件:**
* `:id` が1未満の整数、または数値に変換できない場合はエラーとなること。
* 存在しないIDを指定した場合は `404 Not Found` を返すこと。
* `completed` がブール値（boolean）であることを検証すること。

* **確認方法:** `/todo` 画面の完了チェックボックスを操作し、状態が永続化されること、または存在しないIDに対してリクエストを送り `404` が返ることを確認する。

### REQ-04: TODO削除

* **操作:** 指定したIDのTODOタスクを削除する。
* **エンドポイント:** `DELETE /api/v1/todos/:id`
* **入力:** パラメータ `:id`（1以上の整数）
* **結果:** 成功時はステータスコード `204 No Content` を返し、**レスポンスボディはなし**とする。
* **エラー:** 400、404（指定IDのタスクが存在しない）、500、503。
* **受け入れ条件:**
* 指定されたIDのレコードがデータベースから削除されること。
* 成功時は本文なしの `204` が返却されること。
* 存在しないIDを指定した場合は `404 Not Found` を返すこと。

* **確認方法:** `/todo` 画面の削除ボタンを押し、タスクが一覧から消えること、または `curl -i -X DELETE ...` でステータスコード `204` と本文なしを確認する。

## 3. 共通のデータ・エラー条件

### データベーステーブル構成案 (`sql/todo/020_create_todo_tasks.sql`)

一般的な構成として、以下の `todo_tasks` テーブルを定義します。

* `id` (SERIAL PRIMARY KEY): タスクID（1以上の自動採番整数）
* `title` (VARCHAR(100) NOT NULL): タスクのタイトル
* `completed` (BOOLEAN DEFAULT FALSE NOT NULL): 完了フラグ
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL): 作成日時

### レスポンスおよびエラー仕様

* **成功レスポンスの形式:** 基本的にデータを含む場合は `{"data": ...}` の形、または作成・更新されたリソースオブジェクトを返す。
* **エラーレスポンスの形式:** 原則として `{"error": {"code": ステータスコード, "message": "エラーメッセージ"}}` のJSON形式で統一する。
* **HTTPステータスコードの定義:**
* `400 Bad Request`: リクエストの構文エラーやJSONパース失敗時。
* `422 Unprocessable Entity`: 入力値のバリデーション違反（文字数オーバー、空文字、型違いなど）。
* `404 Not Found`: 対象リソースが存在しない場合。
* `500 Internal Server Error`: 予期せぬサーバー側例外発生時。
* `503 Service Unavailable`: データベース接続タイムアウトや接続断など。

## 4. 環境別確認

* **ローカル開発環境 (`npm run dev`):**
* プロジェクト直下の `.env` ファイルに定義された `DATABASE_URL`（Neon PostgreSQL）を用いて接続する。
* ブラウザで `http://localhost:3000/todo` にアクセスし、CRUD操作が正しく動作することを確認する。

* **本番・プレビュー環境 (Vercel):**
* VercelダッシュボードのEnvironment Variablesに `DATABASE_URL` を設定してデプロイする。
* PreviewおよびProduction環境は同一のNeon DBを参照するため、テストデータの競合に注意しつつ、デプロイ後のURL（`/todo`）およびAPIエンドポイントが正常に稼働することを確認する。
