# TODOアプリ 要件定義書 (`docs/todo/01_requirements.md`)

## 1. 目的・対象範囲

本要件定義は、Express ＋ TypeScript ＋ EJS、および Vercel と Neon PostgreSQL を用いたTODOアプリケーションの構築を目的とします。
既存の `/` および `/api/db-check` のルーティングを残した上で、新たに `/todo` にTODO管理画面を配置します。Preview環境およびProduction環境は同じ Neon DB を参照し、個人情報を扱わず架空のデータのみを対象とします。V1では認証、優先度、絞り込み、タイトル更新機能は対象外とします。

---

## 2. 機能一覧と受け入れ条件

### REQ-01: TODO一覧取得

* **操作**: 画面アクセス時、または必要に応じた再読み込み時に、登録されているTODOの一覧をサーバーから取得・表示する。
* **入力**: なし（GETリクエスト）
* **結果**:
* 成功時: ステータスコード `200` でTODO一覧のJSONデータを返却する（0件の場合は `data: []`）。
* 画面表示: Tailwind CSSを用いたスタイリッシュな一覧として描画する。

* **エラー**:
* データベース接続エラー等の場合、ステータスコード `503` または `500` のエラーレスポンスを返す。

* **受け入れ条件**:
* 登録されているすべてのTODOが一覧表示されること。
* 0件の場合にエラーとならず、空のリストが正しく表示されること。

* **確認方法**: ブラウザで `/todo` にアクセスし、登録済みのTODOが一覧で確認できることを検証する。

### REQ-02: TODO登録

* **操作**: 入力フォームにタイトルを入力し、登録ボタンを押下することで新しいTODOを追加する。
* **入力**: `title`（文字列、前後の空白を除いて1〜100文字）
* **結果**:
* 成功時: ステータスコード `201`（または成功を示すJSON）で作成されたTODOデータを返却し、画面上のリストに即時反映する。

* **エラー**:
* バリデーションエラー（空文字、100文字超過、前後の空白を除いて無効な場合など）はステータスコード `400` または `422` を返す。
* サーバー異常時は `500` または `503` を返す。

* **受け入れ条件**:
* 有効なタイトルが正しくDBに保存され、一覧に追加されること。
* 不正な文字列（長すぎる、空など）の場合には適切なエラーメッセージが表示されること。

* **確認方法**: フォームに有効なタイトルを入力して登録し、一覧に反映されること、および異常値でエラーになることを確認する。

### REQ-03: TODO完了状態の部分更新

* **操作**: TODOのチェックボックス等を操作し、完了・未完了の状態を切り替える。
* **入力**:
* パスパラメータ: `id`（1以上の整数）
* リクエストボディ: 更新対象のフィールド（完了状態など）

* **結果**:
* 成功時: ステータスコード `200` で更新後のTODOデータを返却し、画面の表示を更新する。

* **エラー**:
* 存在しないIDの場合はステータスコード `404` を返す。
* IDが不正またはリクエスト内容が不正な場合は `400` または `422` を返す。

* **受け入れ条件**:
* 指定したIDのTODOの完了状態がトグル（反転）または指定通りに更新されること。

* **確認方法**: 完了チェックボックスをクリックし、状態が保存・反映されること、存在しないIDへのリクエストで404が返ることを確認する。

### REQ-04: TODO削除

* **操作**: 削除ボタンを押下し、不要なTODOを削除する。
* **入力**: パスパラメータ `id`（1以上の整数）
* **結果**:
* 成功時: ステータスコード `204`（本文なし）を返却し、画面の該当TODOを削除する。

* **エラー**:
* 存在しないIDの場合はステータスコード `404` を返す。
* IDが不正な場合は `400` を返す。

* **受け入れ条件**:
* 指定したIDのTODOがデータベースから削除され、画面からも消去されること。

* **確認方法**: 削除ボタンを押し、対象のTODOが画面・DBから消えることを確認する。

## 3. 共通のデータ・エラー条件

* **REST APIのエンドポイント**: `/api/v1/todos` （GET, POST, PATCH, DELETE の4操作）
* **データ構造・バリデーション**:
* `id`: 1以上の整数（DBの自動採番等）
* `title`: 前後の空白を除いて1〜100文字

* **アプリ内定義エラーレスポンス仕様**:
* アプリ内で共通定義したフォーマット（例: `{"success": false, "error": { "code": "...", "message": "..." }}` 等）に準拠する。
* **400 Bad Request**: リクエストの形式不正や必須パラメータの欠落時
* **422 Unprocessable Entity**: バリデーションエラー（文字数オーバー、空文字など）時
* **404 Not Found**: 指定したIDのTODOが存在しない場合
* **500 Internal Server Error**: 予期せぬサーバー内部エラー発生時
* **503 Service Unavailable**: データベース接続失敗時など

## 4. 環境別確認

* **ローカル環境**:
* Expressサーバーを起動し、ブラウザから `/todo` にアクセスして動作確認を行う。

* **Vercel（Preview / Production）環境**:
* デプロイ後、同じ Neon DB を参照していることを確認し、リモート環境上での各CRUD操作（REQ-01〜04）が正常に機能することを検証する。
